#+title: =Leetcode=, задача =440=

Ця задача є іншим варіантом задачі [[file:task386.org][386]], але замість вектора результатом є число. Однак це рішення не
працює при [[id:5590d1fb-9672-4ded-a172-af6dae375ccd][великих значеннях ~n~ і ~k~]] це рішення є настільки неефективним, що не вкладається в обмеження
задачі. Тому використовується геть інше рішення, засноване на логарифмічному підборі результата.

* Пошук рішення

Шукатимемо рішення рекурсивно за допомогою функції ~find~, яка приймає межу ~n~, порядковий номер ~k~ і
поточне значення ~m~, повертаючи результат. Таким чином, достатньо почати з пустого результата і
викликати його послідовно для усіх цифр від ~1~ до ~9~, оскільки число не може починатися з ~0~.

Зауважимо, що при черговому виклику ми можемо не досягти необхідного значення, тоді ми повертаємо ознаку
невдачі у вигляді спеціального значення ~0~. При цьому, однак, очевидно, що рішення завжди є, достатньо
знайти перше ненульове значення.

При обході використовуємо "наскрізну" нумерацію чисел за допомогою індекса ~i~, який почнеться з ~0~ і
буде "просуватися" вперед при обході дерева, поки його значення не співпаде з ~k~.

На великих значеннях параметрів можливе переповнення цілого, тому використовуємо ~u64~.

#+begin_src rust :noweb yes :noweb-ref task440:Дії
  let mut i = 0;
  (1..=9).map(|m| find(n as u64, m, k as u64, &mut i)).find(|&m| m>0).unwrap() as i32
#+end_src

Визначимо саму функцію рекурсивного пошуку.

#+begin_src rust :noweb yes :noweb-ref task440:Визначення
  fn find(n: u64, m: u64, k: u64, i: &mut u64) -> u64 {
      <<task440:find:Дії>>
  }
#+end_src

Якщо поточне значення ~m~ більше ~n~, подальший перебір не має сенсу, тому повертаємо ознаку невдачі.

#+begin_src rust :noweb yes :noweb-ref task440:find:Дії
  if m > n { return 0; }
#+end_src

В іншому випадку ~m~ є значенням, що підходить, тому збільшимо його індекс ~i~.

#+begin_src rust :noweb yes :noweb-ref task440:find:Дії
  *i += 1;
#+end_src

Якщо поточний індекс ~i~ дорівнює ~k~, то ~m~ --- це результат, повертаємо його.

#+begin_src rust :noweb yes :noweb-ref task440:find:Дії
  if *i == k { return m; }
#+end_src

Виконуємо рекурсивний пошук, додаючи ще один розряд (множенням на ~10~) та перебираючи усі можливі цифри
останнього разряду.

#+begin_src rust :noweb yes :noweb-ref task440:find:Дії
  (0..=9).map(|j| find(n, 10*m+j, k, i)).find(|&m| m>0).unwrap_or(0)
#+end_src

Перевіряємо коректність роботи функції на наборі великих чисел. У кожному тесті перше число
використовується як межа ~n~, а друге --- як порядковий номер ~k~. Такий підхід дозволяє перевірити
роботу алгоритму на реальних даних великої розмірності.

  fn test_large_numbers() {
      let test_cases = vec![
          (626615575, 366297423),  // Перша пара
          (724201123, 419746578),  // Друга пара
          (212276511, 161357227),  // Третя пара
          (760772781, 749696464),  // Четверта пара
          (174314809, 101386962),  // П'ята пара
          (156187893, 4429469),    // Шоста пара
          (862411591, 494068084),  // Сьома пара

      for (n, k) in test_cases {
          let result = find_kth_number(n, k);

      }
