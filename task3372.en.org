* Graph Construction

The algorithm's peculiarity is that we need to collect the answer in a specific order at the
end. Therefore, we'll represent the graph as a vector rather than a map. First, we need to determine the
total number of nodes ~n~.

#+begin_src rust :noweb-ref task3372:Definitions
  fn graph(edges: Vec<Vec<i32>>) -> Vec<Vec<usize>> {
      let n = edges.iter().map(|edge| edge[0].max(edge[1])).max().unwrap() as usize + 1;
      edges.into_iter()
          .fold(vec![Vec::new(); n], |mut graph, edge| {
              let (from, to) = (edge[0] as usize, edge[1] as usize);
              graph[from].push(to);
              graph[to].push(from);
              graph
          })
  }
#+end_src

* Finding Degree

We'll define the /=k=-degree/ (or simply degree) of a node as the size of its ~k~-neighborhood, i.e., the number
of nodes reachable from it in ~k~ steps. The ~degree~ function finds the degree of node ~root~ for a given
graph ~graph~.

When finding the maximum degree in the second graph, the neighborhood size is ~k-1~, and we need to

* Finding Solution

To get the solution, it's sufficient to add the maximum degree ~d~ of the =k-1=-neighborhood in the
second graph (which we found [[id:5fe68856-dcf8-43ff-b242-7284c4499286][earlier]]) to the =k=-degree of each node in the first graph, since one edge
will be added during graph connection.

#+begin_src rust :noweb-ref task3372:Actions
  let g = graph(edges1);
  (0..g.len()).map(|n| degree(&g, n, k) + d).collect()
#+end_src 

* Complexity Analysis

Time Complexity: O(n * (n + m))
- where n is the number of nodes (maximum node number + 1)
- m is the number of edges (≤ 10⁵)
- In worst case: n can be of order m (i.e., O(10⁵))
- Then time complexity becomes: O((10⁵)²) = O(10¹⁰)

Space Complexity: O(n + m)
- where n is the number of nodes
- m is the number of edges (≤ 10⁵)
- In worst case: O(10⁵)
